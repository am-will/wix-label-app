# Repository Guidelines

## Project Structure & Module Organization
- `src/main.js`: Electron main process (window lifecycle, Wix API fetch, CSV parsing, scheduling, printing, persistence).
- `src/preload.js`: secure IPC bridge exposed to renderer.
- `src/index.html`: renderer UI, styles, and client-side interaction logic.
- `scripts/start-electron.js`: dev launcher used by `npm start` (Linux-friendly flags).
- `assets/`: static app assets (logos/icons).
- `WINDOWS_TESTING.md`: Windows setup and validation notes.
- Build output goes to `dist/` (generated by electron-builder).

## Build, Test, and Development Commands
- `npm install` or `npm ci`: install dependencies.
- `npm start`: run the desktop app locally.
- `npm run build` or `npm run build:linux`: build Linux AppImage.
- `npm run build:win`: build Windows installer (`.exe`) when environment supports it.
- `npm run pack`: create unpacked build directory for quick artifact checks.

## Coding Style & Naming Conventions
- Language stack is plain JavaScript + HTML/CSS (no TypeScript).
- Use 2-space indentation and semicolons, matching `src/main.js` and `src/index.html`.
- Prefer `const`/`let` over `var`; keep functions focused and side effects explicit.
- Use descriptive camelCase for variables/functions (e.g., `loadSettings`, `fetchWixOrders`).
- Keep IPC channel names and settings keys clear and stable to avoid renderer/main drift.

## Testing Guidelines
- No automated test suite is currently configured.
- Validate changes manually via `npm start`:
  - pull orders (or CSV import),
  - preview labels,
  - print/save PDF,
  - verify schedule behavior,
  - confirm settings persist after restart.
- For Windows-specific checks, follow `WINDOWS_TESTING.md`.

## Commit & Pull Request Guidelines
- Follow Conventional Commit style seen in history: `feat: ...`, `docs: ...`, `fix: ...`.
- Keep commits scoped to one concern and include affected area when helpful.
- PRs should include:
  - concise summary,
  - test notes (manual steps performed),
  - screenshots/GIFs for UI changes,
  - linked issue/ticket when available.
